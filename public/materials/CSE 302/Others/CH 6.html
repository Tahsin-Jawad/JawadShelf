1. Introduction & Database Design Phases

PDF Pages: 1 - 3

E-R Data Model কী?

E-R Model-এর পূর্ণরূপ হলো Entity-Relationship Data Model। এটি একটি উচ্চমানের (High-level) Conceptual Data Model যা বাস্তব পৃথিবীর বিভিন্ন Object (Entity) এবং তাদের মধ্যবর্তী সম্পর্ককে (Relationship) চিত্র বা Diagram-এর মাধ্যমে প্রকাশ করে।

Database Design-এর ৩টি প্রধান Phase (পরীক্ষার জন্য অতীব গুরুত্বপূর্ণ):

Phase 1
1. Conceptual Design

User Requirements থেকে ER Diagram তৈরি করা হয়। এটি Platform-independent।

Output: ER Diagram
Phase 2
2. Logical Design

ER Diagram-কে Relational Schema বা Table Structure (Columns & Types)-এ রূপান্তর করা হয়।

Output: Relational Schema
Phase 3
3. Physical Design

নির্দিষ্ট DBMS (যেমন MySQL, Oracle)-এ Storage, Indexing এবং Physical Tables তৈরি।

Output: Actual Database
Exam Formula:

Requirement Specification ➔ Conceptual Design (ERD) ➔ Logical Design (Schema) ➔ Physical Design (DBMS Implementation)

2. Core ER Components & Notation Symbols

PDF Pages: 4 - 5 & 8

এই বইটিতে Chen Model Notation ব্যবহার করা হয়েছে। ER Model মূলত ৩টি মূল স্তম্ভের ওপর দাঁড়িয়ে আছে: Entity Set, Attribute, এবং Relationship Set।

Symbol / Notation Component Name সংজ্ঞা & মূল কাজ বাস্তব উদাহরণ
Rectangle ( □ ) Entity Set বাস্তব পৃথিবীর এমন কোনো অবজেক্ট যার তথ্য ডাটাবেজে রাখা হয়। Student, Customer, Course
Double Rectangle ( ⧈ ) Weak Entity Set যার নিজস্ব Primary Key নেই, অন্য Entity-র ওপর নির্ভরশীল। Payment (Loan-এর অধীনে)
Oval / Ellipse ( ○ ) Attribute Entity-র বৈশিষ্ট্য বা Data Properties প্রকাশ করে। Name, Age, Student_ID
Diamond ( ◇ ) Relationship Set একাধিক Entity-র মধ্যে বিদ্যমান সম্পর্ক নির্দেশ করে। Enrolls, Works_In, Borrows
Double Diamond ( ◈ ) Identifying Relationship Weak Entity এবং তার Strong Parent-এর মধ্যবর্তী সম্পর্ক। Loan_Payment (Loan ↔ Payment)

3. Attribute Classification & Descriptive Attributes

PDF Pages: 6 - 10, 15

1. Simple Attribute vs 2. Composite Attribute

  • Simple (Atomic): যাকে আর ছোট অংশে ভাগ করা যায় না। যেমন: Gender, Salary
  • Composite: যে Attribute-কে একাধিক Sub-attributes-এ ভাঙা যায়। যেমন: Address ➔ (Street, City, Zip) অথবা Name ➔ (First_Name, Last_Name)।

3. Multivalued Attribute vs 4. Derived Attribute

  • Multivalued (Double Oval): একটি Entity-র জন্য একাধিক মান থাকতে পারে। যেমন: Phone_Number, Degrees।
  • Derived (Dashed Oval): ডাটাবেজে সরাসরি Store না করে অন্য Attribute (যেমন DOB) থেকে Calculate করা হয়। যেমন: Age, Length_of_Employment।

Relationship / Descriptive Attributes (Pages 7, 9, 10)

কিছু Attribute এককভাবে কোনো Entity-র নিজস্ব নয়, বরং দুটি Entity-র মধ্যবর্তী Relationship Set-এর ওপর নির্ভর করে। একে Descriptive Attribute বলা হয়।

উদাহরণ: Student ➔ Enrolls (Relationship) ➔ Course
এখানে access_date বা grade কেবল Student বা কেবল Course-এর নয়, এটি Enroll সম্পর্কের Descriptive Attribute (Diagram-এ Diamond-এর সাথে সরাসরি লাইন দিয়ে যুক্ত হয়)।

4. Relational Keys Deep Dive

PDF Pages: 11 - 12

Key Set Relationship: Super Key ⊃ Candidate Key ⊃ Primary Key

Super Key: এক বা একাধিক Attribute যা কোনো Row-কে Uniquely Identify করতে পারে (Unnecessary Attributes থাকতে পারে)।
Candidate Key: Minimal Super Key (যেকোনো একটি Attribute সরালে আর Unique থাকে না)।
Primary Key: Candidate Key-গুলোর মধ্যে থেকে Database Design-এর জন্য বেছে নেওয়া মূল Unique Identifier (ER Diagram-এ Underline করা হয়)।

Composite Key

একাধিক Attribute একত্রে মিলে তৈরি হওয়া Primary Key। যেমন: (Course_Code, Trimester)

Foreign Key

একটি Table-এর Attribute যা অন্য Table-এর Primary Key-কে Refer করে Referential Integrity বজায় রাখে।

Partial Key / Discriminator

Weak Entity-র নিজস্ব আংশিক Key (Dashed Underline), যা Strong Entity-র PK-র সাথে মিলে Unique হয়।

5. Strong Entity vs Weak Entity Set

PDF Pages: 13, 14

Strong Entity Set

  • নিজস্ব পূর্ণাঙ্গ Primary Key থাকে।
  • অন্য কোনো Entity-র ওপর অস্তিত্ব নির্ভর করে না (Independent)।
  • Symbol: Single Rectangle ( □ )
  • Example: Customer, Employee, Loan

Weak Entity Set

  • নিজস্ব Primary Key থাকে না, কেবল Partial Key থাকে।
  • Strong Entity-র ওপর সম্পূর্ণরূপে নির্ভর করে (Existence Dependent)।
  • Symbol: Double Rectangle ( ⧈ )
  • PK Formula: Parent PK + Partial Key
  • Example: Payment (depends on Loan), Dependent (depends on Employee)।

6. Classification of Relationship Sets

PDF Pages: 16 - 21
1. Identifying vs Non-Identifying

Identifying (Double Diamond): Child entity-র PK গঠনে Parent-এর PK প্রয়োজন হয়। (e.g., Loan ↔ Payment)
Non-Identifying (Single Diamond): Child entity-র নিজস্ব PK থাকে, Parent PK শুধু FK হিসেবে কাজ করে। (e.g., Branch ↔ Book)

2. Recursive Relationship (Unary)

যখন একই Entity Set নিজের সাথেই সম্পর্ক তৈরি করে। (PDF Page 20)
Example: Employee --(manages)--> Employee (Manager and Worker both are Employees).

3. Parallel Relationship Set

একই দুটি Entity Set-এর মধ্যে একাধিক আলাদা Relationship বিদ্যমান থাকা (PDF Page 21)।
Example: Student এবং Course-এর মধ্যে ২টি সম্পর্ক: Takes (ছাত্র হিসেবে) এবং TA (Teaching Assistant হিসেবে)।

7. Mapping Cardinalities & Participation Constraints

PDF Pages: 22 - 26

A. Mapping Cardinality Ratios:

One-to-One (1:1)
HOD ↔ Dept
One-to-Many (1:N)
Faculty ↔ Class
Many-to-One (M:1)
Employee ↔ Dept
Many-to-Many (M:N)
Student ↔ Course

B. Participation Constraints (Page 26):

Total Participation (Double Line ══) Entity Set-এর প্রতিটি Entity-কে বাধ্যতামূলকভাবে সম্পর্কের মধ্যে অংশ নিতে হবে।
Example: প্রতিটি Payment-কে অবশ্যই কোনো না কোনো Loan-এর সাথে যুক্ত থাকতে হবে।
Partial Participation (Single Line ──) Entity Set-এর কিছু Entity অংশ নিতে পারে, আবার নাও পারে।
Example: সব Employee কোনো Dept-এর Manager নয়।

8. Extended E-R Features (EER)

PDF Pages: 27 - 29

1. Generalization (Bottom-Up)

একাধিক নিম্ন-স্তরের Entity-র সাধারণ বৈশিষ্ট্যসমূহকে একত্রিত করে উচ্চ-স্তরের Entity তৈরির প্রক্রিয়া (Triangle labeled "IS A")।
Example: Faculty + Student ➔ Person

2. Specialization (Top-Down)

একটি উচ্চ-স্তরের Entity-কে তার নির্দিষ্ট বৈশিষ্ট্যের ভিত্তিতে সাব-এন্টিটিতে বিভক্ত করা।
Example: Employee ➔ Tester, Developer

3. Aggregation (Page 29)

যখন একটি Relationship এবং Entity-র সম্পর্ককে নিজে একটি Entity হিসেবে গণ্য করে অন্য সম্পর্কের সাথে যুক্ত করা হয়।
Example: Center + Course ➔ (Enquired by Visitor)

9. Step-by-Step ERD Drawing Rules for Exam

PDF Pages: 30 - 32
  1. Identify Entities: সকল Noun/Object চিহ্নিত করে Rectangle (□) আঁকো।
  2. Define Attributes: প্রতিটি Entity-র বৈশিষ্ট্য বসাও। Primary Key-তে Underline এবং Composite/Derived/Multivalued সঠিকভাবে চিহ্নিত করো।
  3. Identify Relationships: Entity-গুলোর মধ্যে Diamond (◇) দিয়ে কানেকশন তৈরি করো।
  4. Determine Cardinalities: 1:1, 1:N, নাকি M:N তা লাইনের পাশে নির্দেশ করো।
  5. Identify Weak Entities & Identifying Relationships: Weak Entity-র ক্ষেত্রে Double Rectangle (⧈) এবং Double Diamond (◈) ও Partial Key-তে Dashed Underline ব্যবহার করো।
