Slide 2: Relational Query Languages

Slide Content Breakdown

  • Relational Query Language: Language in which user requests information from the database.
  • Procedural Language: User instructs the system to perform a sequence of operations to compute the result (HOW to get the data).
  • Non-procedural / Declarative Language: User describes the desired information without giving a specific procedure (WHAT data to get, e.g., SQL).
  • "Pure" Languages: Relational Algebra (Procedural), Tuple Relational Calculus (Non-procedural), Domain Relational Calculus (Non-procedural).

Real-Life Analogy (সহজ ব্যাখ্যা):

মনে কর তুমি রেস্টুরেন্টে গিয়ে খাবার অর্ডার করছ।
১. Declarative (SQL): তুমি শুধু বললে "আমাকে একটা বিফ বার্গার দিন।" তুমি কি শেফকে বলেছ কীভাবে রান্না করতে হবে? না! এটা হলো Non-procedural।
২. Procedural (Relational Algebra): তুমি যদি কিচেনে গিয়ে বল—"প্রথমে পাউরুটি স্যাঁকো, মাংস ভাজো, তার ওপর চিজ দাও, তারপর একসাথে জোড়া দাও।" এখানে তুমি কীভাবে বানাবে তার step-by-step নির্দেশ দিচ্ছ। এটাই হলো Procedural Language!

Procedural (Relational Algebra)

Focuses on execution steps and mathematical operations on sets.

Non-Procedural (SQL / Calculus)

Focuses purely on the specification of the final desired result.

Slide 4: Select Operation ($\sigma$)

Syntax & Formula

$\sigma_{p}(r)$

যেখানে $\sigma$ হলো Selection Symbol, $p$ হলো Selection Predicate (শর্ত/Condition), এবং $r$ হলো Relation (Table)-এর নাম।

Teacher's Lecture Notes:

Select ($\sigma$) অপারেটর টেবিল থেকে নির্দিষ্ট কিছু Row/Tuple (হরিজন্টাল ফিল্টারিং) বেছে নেয় যা একটি নির্দিষ্ট Predicate বা কন্ডিশন পূরণ করে।

মনে রাখার টেকনিক:

Select = Row Selection! এটি কলাম কাটে না, পুরো রো (Row)-কে ফিল্টার করে আউটপুটে নিয়ে আসে।

Slide Example Solution:

Query: Select those tuples of the instructor relation where the instructor is in the "Physics" department.

$\sigma_{dept\_name = \text{"Physics"}}(instructor)$
Resulting Output Relation:
ID name dept_name salary
22222 Einstein Physics 95000
33456 Gold Physics 87000

Slide 5: Complex Predicates in Select

Selection Predicate Building Blocks:

Selection predicate-এ আমরা নিচের তুলনাভিত্তিক অপারেটর (Comparison Operators) ব্যবহার করতে পারি:

$=, \neq, >, \ge, <, \le$

এবং একাধিক শর্তকে যুক্ত করতেLogical Connectives ব্যবহার করি:

  • Logical AND ($\land$): উভয় শর্ত সত্য হতে হবে।
  • Logical OR ($\lor$): যেকোনো একটি শর্ত সত্য হলেই হবে।
  • Logical NOT ($\neg$): শর্তকে উল্টে দেয় (Negation)।
Example Query:

Find the instructors in Physics with a salary greater than $90,000.

$\sigma_{dept\_name = \text{"Physics"} \land salary > 90000}(instructor)$

Slide 6: Select Operation vs. SQL WHERE Clause

Relational Algebra to SQL Comparison:

অত্যন্ত গুরুত্বপূর্ণ কনসেপ্ট! ছাত্র-ছাত্রীরা যে ভুলটা বেশি করে—Relational Algebra-র $\sigma$ (Select) কিন্তু SQL-এর SELECT ক্লজ নয়! Relational Algebra-র $\sigma$ সরাসরি SQL-এর WHERE ক্লজের সাথে মিলে।

Relational Algebra
$\sigma_{Dno = 4 \land Salary > 25000}(EMPLOYEE)$
Equivalent SQL
SELECT *
FROM EMPLOYEE
WHERE Dno = 4 AND Salary > 25000;

Slide 7: Project Operation ($\pi$)

Syntax & Formula

$\pi_{A_1, A_2, \dots, A_k}(r)$

যেখানে $A_1, A_2, \dots, A_k$ হলো Attributes (Column Name)-এর তালিকা এবং $r$ হলো Relation।

Vertical Filtering & Duplicate Removal Rules:

Project ($\pi$) অপারেটর টেবিল থেকে নির্দিষ্ট কিছু Column (ভার্টিক্যাল ফিল্টারিং) রেখে বাকি কলামগুলো বাদ দিয়ে দেয়।

GOLDEN EXAM RULE:

যেহেতু Relational Algebra গাণিতিক Set (Mathematical Set)-এর নীতি অনুসরণ করে, তাই Project অপারেশন প্রয়োগ করার পর প্রাপ্ত ফলাফলে যদি কোনো Duplicate Rows চলে আসে, তবে ডুপ্লিকেট রোগুলো স্বয়ংক্রিয়ভাবে মুছে যাবে (Duplicate rows are automatically removed)!

Slide 10: Project Operation vs. SQL SELECT DISTINCT

Project ($\pi$) and SQL SELECT DISTINCT:

SQL-এর সাধারণ SELECT কিন্তু বাই-ডিফল্ট ডুপ্লিকেট মোছে না (Multiset/Bag behavior)। কিন্তু Relational Algebra-র $\pi$ সবসময় ডুপ্লিকেট মুছে দেয়। তাই SQL-এ $\pi$-এর হুবহু সমতুল্য রিপ্রেজেন্টেশন লিখতে হলে আমাদের SELECT DISTINCT ব্যবহার করতে হয়!

Relational Algebra
$\pi_{gender, Salary}(EMPLOYEE)$
Equivalent SQL
SELECT DISTINCT gender, salary
FROM EMPLOYEE;

Slide 11: Composition of Operations

Composition (একের ভেতর অন্য অপারেটর):

যেহেতু একটি রিলেশনাল অ্যালজেব্রা অপারেশনের ফলাফল নিজেই একটি রিলেশন, তাই আমরা একাধিক অপারেশনকে জোড়া লাগিয়ে একটি একক এক্সপ্রেশন (Composed Expression) তৈরি করতে পারি।

Query: Find the names of all instructors in the Physics department.
$\pi_{name}(\sigma_{dept\_name = \text{"Physics"}}(instructor))$

প্রসেসিং ক্রমানুসার (Execution Order):

  1. ভিতরের অংশ আগে চলবে: $\sigma_{dept\_name = \text{"Physics"}}(instructor)$ পদার্থবিজ্ঞান বিভাগের শিক্ষকদের রো বের করবে।
  2. বাইরের অংশ পরে চলবে: $\pi_{name}(\dots)$ সেই ফিল্টার করা রো থেকে কেবল শিক্ষকগুলোর নাম (name) কলাম রাখবে।

Slide 12: Rename Operation ($\rho$)

Syntax Forms

$\rho_{X}(E)$  →  Expression $E$-এর ফলাফল টেবিলকে $X$ নামে রিনেম করে।
$\rho_{X(A_1, A_2, \dots, A_n)}(E)$  →  টেবিলের নাম $X$ এবং তার কলামগুলোর নাম $A_1, A_2, \dots$ এ রিনেম করে।

রিনেম অপারেটর ($\rho$ - Rho) ব্যবহার করা হয় কোনো ক্যোয়ারির ইন্টারমিডিয়েট আউটপুট টেবিলকে একটি নির্দিষ্ট নাম বা কলামগুলোকে নতুন নাম দেওয়ার জন্য। SQL-এ এটি AS ক্লজ দিয়ে করা হয়।

Slide 14: Sequential vs In-line Expressions

Two Ways to Write Complex Queries:

জটিল ক্যোয়ারি লেখার সময় আমরা দুইটা অ্যাপ্রোচ নিতে পারি:

  1. In-line Single Expression: ব্র্যাকেট নেস্ট করে এক লাইনে পুরোটা লেখা।

Slide 17: Union Operation ($\cup$) & Compatibility

Union Compatibility Requirements (পরীক্ষার ভাইটাল টপিক!)

দুইটি রিলেশন $r$ এবং $s$-এর মধ্যে Union ($r \cup s$), Intersection ($r \cap s$), অথবা Set Difference ($r - s$) করতে হলে তাদেরকে অবশ্যই Union Compatible হতে হবে। এর জন্য ২টি শর্ত পূরন করা বাধ্যতামূলক:

  1. Same Arity: $r$ এবং $s$ উভয় টেবিলেই কলামের সংখ্যা (Number of attributes) সমান হতে হবে।
  2. Compatible Domains: $r$-এর $i$-তম কলামের ডাটা টাইপ এবং $s$-এর $i$-তম কলামের ডাটা টাইপ হুবহু এক হতে হবে ($Domain(r_i) = Domain(s_i)$)।
Slide Example Query:

Find all courses taught in Fall 2009 semester, or in Spring 2010 semester, or in both.

$\pi_{course\_id}(\sigma_{semester = \text{"Fall"} \land year = 2009}(section)) \;\cup\; \pi_{course\_id}(\sigma_{semester = \text{"Spring"} \land year = 2010}(section))$

Slide 21: Intersection Operation ($\cap$)

Definition

$r \cap s$ কেবল সেই সকল টুপল/রো রিটার্ন করে যা $r$ এবং $s$ উভয় টেবিলেই বিদ্যমান (Common Tuples)।

Example Query:

Find the set of all courses taught in BOTH Fall 2009 AND Spring 2010 semesters.

$\pi_{course\_id}(\sigma_{semester = \text{"Fall"} \land year = 2009}(section)) \;\cap\; \pi_{course\_id}(\sigma_{semester = \text{"Spring"} \land year = 2010}(section))$
Page 22 / 68

Slide 22: Intersection Derivation using Difference

Mathematical Equivalence Formula

ইন্টারসেকশন ($\cap$) কিন্তু কোনো মৌলিক (Fundamental) অপারেটর নয়! এটি Set Difference ($-$) অপারেটর ব্যবহার করে প্রকাশ করা যায়:

$r \cap s = r - (r - s)$

Slide 23: Set Difference Operation ($-$)

Meaning of $r - s$

$r - s$ এমন সব টুপল বের করে আনবে যা প্রথম রিলেশন $r$-এ আছে কিন্তু দ্বিতীয় রিলেশন $s$-এ নেই।

Example Query:

Find all courses taught in Fall 2009 semester BUT NOT in Spring 2010 semester.

Slide 26: Assignment Operation ($\leftarrow$)

Slide 27: Cartesian Product Operation ($\times$)

Definition

Cartesian Product ($r \times s$) প্রথম রিলেশন $r$-এর প্রতিটি টুপলকে দ্বিতীয় রিলেশন $s$-এর প্রতিটি টুপলের সাথে জোড়া (Combine) তৈরি করে।

Arity Rule: যদি $r$-এর কলাম সংখ্যা $n_1$ এবং $s$-এর কলাম সংখ্যা $n_2$ হয়, তবে $r \times s$-এর কলাম সংখ্যা হবে $n_1 + n_2$।

Cardinality Rule: যদি $r$-এর রো সংখ্যা $m_1$ এবং $s$-এর রো সংখ্যা $m_2$ হয়, তবে $r \times s$-এর রো সংখ্যা হবে $m_1 \times m_2$!

Slide 37: Join Operation ($\bowtie$) Motivation

Why do we need Join ($\bowtie$)?

Cartesian Product ($\times$) করার পর বেশিরভাগ রো-ই অকার্যকর তথ্য প্রদান করে। কাজের রো পেতে আমাদের সবসময় Cross Product-এর পর Selection Condition দিতে হয়:

Slide 39: General Definition of Theta Join ($\bowtie_\theta$)

Theta Join Mathematical Formula

$R \bowtie_{\theta} S = \sigma_{\theta}(R \times S)$

যেখানে $R, S$ হলো রিলেশন এবং $\theta$ হলো জয়েন কন্ডিশন (Join predicate)।

Exam Definition:

Theta Join ($\bowtie_\theta$) is a derived relational operation that combines tuples from two relations that satisfy a specified predicate condition $\theta$.

Question: Find the names of all customers who have a loan at the Perryridge branch.

  1. borrower এবং loan টেবিল সাধারণ কলাম loan_number অনুযায়ী জয়েন হবে।

  3. ফাইনালি customer_name কলামটি প্রজেক্ট হবে।
Step 7: Key Concept & Pitfalls: ভুল করে শুধুমাত্র borrower টেবিল ব্যবহার করলে হবে না, কারণ borrower টেবিলে ব্রাঞ্চের নাম থাকে না!

$\pi_{customer\_name}(\sigma_{branch\_name = \text{"Perryridge"}}(borrower \bowtie loan))$

Relational Algebra Complete Cheat Sheet

Quick Exam Reference for Symbols, Syntax, Rules, and Descriptions

Operator Symbol Syntax Purpose / Explanation Key Exam Rule
Select $\sigma$ $\sigma_p(r)$ Selects rows satisfying predicate $p$. Row filtering only. No columns removed.
Project $\pi$ $\pi_{A_1, A_2}(r)$ Keeps listed columns, discards others. Automatically eliminates duplicates!
Union $\cup$ $r \cup s$ Combines tuples from both relations. Requires Union Compatibility (Same Arity & Domains).
Set Difference $-$ $r - s$ Tuples in $r$ but NOT in $s$. Requires Union Compatibility. Used for "NOT IN" queries.
Cartesian Product $\times$ $r \times s$ Pairs every tuple of $r$ with every tuple of $s$. Output rows = $m_1 \times m_2$, Columns = $n_1 + n_2$.
Rename $\rho$ $\rho_{x}(E)$ Gives name $x$ to expression result $E$. Used in self-joins and intermediate assignments.
Theta Join $\bowtie_\theta$ $r \bowtie_\theta s$ Cross Product followed by Selection condition. $r \bowtie_\theta s = \sigma_\theta(r \times s)$.
Aggregate $\mathcal{G}$ $_{G}\mathcal{G}_{F(A)}(r)$ Performs AVG, SUM, COUNT, MIN, MAX grouped by $G$. Group attributes go on left, aggregate functions on right.

Operator Comparison Matrix

Comparing Commonly Confused Relational Algebra Concepts

Selection ($\sigma$) vs. Projection ($\pi$)

  • Selection ($\sigma$): Filters rows/tuples based on a condition. Keeps all columns intact.
  • Projection ($\pi$): Filters columns/attributes. Discards unlisted columns and removes duplicate rows.

Cartesian Product ($\times$) vs. Join ($\bowtie$)

  • Cartesian Product ($\times$): Unconditional pairing of all rows ($m \times n$). Creates many invalid rows.
  • Join ($\bowtie$): Conditional pairing ($r \bowtie_\theta s = \sigma_\theta(r \times s)$). Only keeps rows matching condition $\theta$.
