Joined Expressions Intro

Joined operations take two relations as input and return another relation as a result. They combine records from two tables based on conditions. 

-- Basic Cartesian Product (Cross Join)
SELECT * FROM student, takes;

Teacher's Explanation:

মনে করো তোমার কাছে দুটো টেবিল আছে: student এবং takes। সাধারণ কমা (,) দিলে রিলেশনাল এলজেব্রার Cartesian Product ($R \times S$) হয়, যা অপ্রয়োজনীয় ডাটা তৈরি করে। তাই আমরা Join Clause ব্যবহার করি যাতে শুধুমাত্র অর্থপূর্ণ মিলযুক্ত ডাটা যুক্ত হয়।

Joined Relations: Types & Condition Forms

Join Types

  • INNER JOIN (Default)
  • LEFT OUTER JOIN
  • RIGHT OUTER JOIN
  • FULL OUTER JOIN

Join Conditions

  • NATURAL
  • ON <predicate>
  • USING (A1, A2, ...)

Teacher's Explanation:

Join মূলত ২ ভাগে বিভক্ত: Inner Join (যা শুধু মিল থাকা সারিগুলো দেখায়) এবং Outer Join (যা অমিল থাকা সত্ত্বেও ডাটা ধরে রাখে)। আর এগুলোকে তিন উপায়ে যুক্ত করা যায়: NATURAL, ON শর্ত দিয়ে, অথবা USING দিয়ে নির্দিষ্ট কলাম নাম বলে।

Natural Join Deep Dive & Pitfalls

NATURAL JOIN matches tuples that have the same values for all common attributes in both relations. It automatically removes duplicate columns in the output. 

-- Safe Natural Join Example
SELECT name, course_id
FROM instructor NATURAL JOIN teaches;

-- Pitfall Example: Danger of extra common attributes!
-- If 'instructor' and 'student' both have 'dept_name', it matches BOTH ID and dept_name!
SELECT * FROM instructor NATURAL JOIN student; -- May return empty unexpectedly!

Teacher's Warning (পরীক্ষায় পপুলার প্রশ্ন):

NATURAL JOIN খুব সুবিধাজনক কারণ ON দেওয়া লাগে না। কিন্তু বিপদ হলো, দুটি টেবিলে যদি ২ বা ৩টি কলামের নাম একই থাকে (যেমন dept_name এবং ID), তবে এটি দুটোই ম্যাচ করতে যাবে। ফলে অপ্রয়োজনীয় ফিল্টারিং হয়ে ডাটা হারিয়ে যেতে পারে। এজন্য পরীক্ষার খাতায় নিরাপত্তার জন্য USING(ID) বা ON ব্যবহার করা ভালো।

Outer Joins (Left, Right, Full)

Outer joins preserve tuples that would be lost in an inner join by padding missing values with NULL.

LEFT OUTER JOIN

Keeps ALL rows from the left table, even if no match exists in the right table.

RIGHT OUTER JOIN

Keeps ALL rows from the right table, padding left side missing attributes with NULL.

FULL OUTER JOIN

Combines Left and Right Outer joins. Preserves tuples from both sides.

-- Find students who have NEVER taken any course
SELECT student.ID, student.name
FROM student LEFT OUTER JOIN takes ON student.ID = takes.ID
WHERE takes.course_id IS NULL;

Teacher's Explanation:

পরীক্ষায় এমন প্রশ্ন আসবেই: "এমন স্টুডেন্টদের বের করো যারা কোনো কোর্স নেয়নি" বা "এমন ডিপার্টমেন্ট বের করো যেখানে কোনো শিক্ষক নেই"। এটি সমাধানের মূল ট্রিক হলো LEFT OUTER JOIN করা এবং ডান টেবিলের Primary Key-তে WHERE right_table.key IS NULL চেক করা!

Views & Virtual Relations

A view provides a mechanism to hide certain data from the view of certain users. It is a "virtual table" that is not stored physically; rather, its definition is saved. 

-- Creating a View
CREATE VIEW faculty_no_salary AS
SELECT ID, name, dept_name
FROM instructor;

-- Querying a View (Just like a normal table)
SELECT * FROM faculty_no_salary WHERE dept_name = 'Comp. Sci.';

Teacher's Explanation:

ধরো কোনো ক্লার্ককে শিক্ষকদের নাম ও ডিপার্টমেন্ট দেখাতে হবে, কিন্তু বেতন (Salary) দেখানো নিষেধ। তখন আমরা মূল টেবিল লুকানোর জন্য একটি View তৈরি করি। View কোনো নতুন ডাটা মেমোরিতে স্টোর করে না, এটি কেবল একটি সংরক্ষিত SQL কুয়েরি!

PDF Page 7

View Modifications & Updatable Views

An update/insert through a view is allowed ONLY IF the view is Updatable.

Conditions for Updatable View:
  • The FROM clause has only ONE database relation.
  • The SELECT clause contains attribute names (no expressions, aggregates like SUM/AVG, DISTINCT).
  • No GROUP BY or HAVING clause.

Teacher's Explanation:

সব View-তে INSERT বা UPDATE করা যায় না! যদি একটি View একাধিক টেবিল থেকে জয়েন করে তৈরি হয় অথবা AVG(salary) ব্যবহার করে, তবে ডাটাবেজ বুঝতে পারে না ডাটাটা কোন আসল সারিতে ইনসার্ট হবে। তাই শুধুমাত্র সিঙ্গেল টেবিলের সিম্পল View উপাদানে আপডেট করা সম্ভব।

Integrity Constraints & Check Clause

Integrity constraints guard against accidental damage to the database, ensuring that authorized changes do not result in a loss of data consistency. 

CREATE TABLE department (
    dept_name VARCHAR(20),
    building  VARCHAR(15),
    budget    NUMERIC(12,2) CHECK (budget > 0),
    PRIMARY KEY (dept_name)
);

Teacher's Explanation:

Constraint মানে নিয়ম। যেমন: বাজেট কখনো ঋণাত্মক হতে পারবে না (CHECK (budget > 0))। কেউ যদি ভুল করে $-5000$ ইনসার্ট করার চেষ্টা করে, SQL সাথে সাথে Error ছুঁড়ে মারবে এবং ডাটাবেজ সুরক্ষিত থাকবে।

Referential Integrity & Foreign Keys Cascading

Ensures that a value that appears in one relation for a given set of attributes also appears for a certain set of attributes in another relation. 

CREATE TABLE course (
    course_id VARCHAR(8),
    dept_name VARCHAR(20),
    PRIMARY KEY (course_id),
    FOREIGN KEY (dept_name) REFERENCES department(dept_name)
        ON DELETE CASCADE
        ON UPDATE CASCADE
);

Teacher's Explanation:

ON DELETE CASCADE অত্যন্ত গুরুত্বপূর্ণ! ধরা যাক, 'CSE' ডিপার্টমেন্ট ডিলেট করে দেওয়া হলো। তাহলে course টেবিলে থাকা সমস্ত CSE কোর্সও আপনা-আপনি ডিলেট হয়ে যাবে। যদি CASCADE না দাও, তবে ডাটাবেজ ডিপার্টমেন্ট ডিলেট করতেই দেবে না!

Transactions & Access Authorization

Transactions are unit sequences of query executions that maintain ACID properties. Authorization controls privileges like SELECT, INSERT, UPDATE, DELETE. 

-- Authorization Syntax
GRANT SELECT, UPDATE (salary) ON instructor TO Amit;
REVOKE SELECT ON instructor FROM Amit;

Teacher's Explanation:

GRANT দিয়ে ইউজারের এক্সেস দেওয়া হয় এবং REVOKE দিয়ে তা কেড়ে নেওয়া হয়। পরীক্ষায় প্রশ্ন আসে "Amit-কে শুধু Salary দেখার অনুমতি দাও" -> GRANT SELECT(salary) ON instructor TO Amit;

Problem 1: Find titles of courses in Comp. Sci. department with > 3 credits

SELECT title FROM course WHERE dept_name = 'Comp. Sci.' AND credits > 3;

Problem 2: Find all courses taught by instructor 'Einstein'

SELECT course.course_id, course.title
FROM teaches
JOIN instructor ON teaches.ID = instructor.ID
JOIN course ON teaches.course_id = course.course_id
WHERE instructor.name = 'Einstein';

Problem 3: Find maximum salary among all instructors

SELECT MAX(salary) AS max_salary FROM instructor;

Problem 4: Find instructors who have highest salary using subquery

SELECT name, salary FROM instructor 
WHERE salary = (SELECT MAX(salary) FROM instructor);

Problem 5: Find enrolment of each section offered in Spring 2018

SELECT course_id, sec_id, COUNT(ID) AS enrollment
FROM takes
WHERE semester = 'Spring' AND year = 2018
GROUP BY course_id, sec_id;
