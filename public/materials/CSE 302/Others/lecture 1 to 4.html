01

Data vs Information

সহজ ভাষায় Concept (Bangla Intuition):

Data হচ্ছে একদম কাঁচা বা অসংসোধিত ফ্যাক্টস (Raw Facts)। এর একা একা কোনো নির্দিষ্ট অর্থ নাও থাকতে পারে। আর যখন এই Data-কে প্রসেস করে বা সাজিয়ে অর্থপূর্ণ কোনো মেসেজে রূপান্তর করা হয়, তখন তাকে Information বলে।

Data (Raw Material)

Unorganized, unprocessed facts, figures, symbols, or observations. Holds no inherent context or direct meaning on its own.

Examples: "EWU", "101", "3.95", "Mr. X"

Information (Processed)

Data that has been processed, structured, or contextualized to provide meaning and utility for decision making.

Example: "Student Mr. X (ID: 101) at EWU achieved a GPA of 3.95."

(Inputs)
Processing & Context
(DBMS Logic)
Information
(Meaningful Output)
02

Database & DBMS Fundamentals

Why do we need a Database?

A Database is an organized collection of logically related data. It allows organizations to systematically perform core CRUD operations: Create, Read, Update, and Delete.

Comparison: DBMS vs RDBMS vs NoSQL

Feature DBMS RDBMS NoSQL
Data Storage File format / Hierarchical Tabular (Tables with Rows & Columns) Document (JSON/BSON), Key-Value, Graph
Relationships Not supported or primitive Explicit via Foreign Keys Non-relational / Nested structures
ACID Compliance No Strictly Enforced BASE model (Eventual Consistency)
03

Database Architecture (2-Tier vs 3-Tier)

সহজ ভাষায় Concept (Bangla Intuition):

2-Tier Architecture এ ক্লায়েন্ট সরাসরি ডাটাবেজের সাথে যোগাযোগ করে। কিন্তু 3-Tier Architecture এ মাঝে একটি Application Server (Business Logic Layer) থাকে যা সিস্টেমকে নিরাপদ ও Scalable করে!

2-Tier Architecture

Client App (UI + Logic)
Database Server

3-Tier Architecture

User Client (Presentation Layer)
Application Server (Business Logic)
Database Server (Data Layer)

Database Schemas & Data Independence

Schema (Blueprint)

The overall logical design/structure of the database. Rarely changes once designed.

Instance (Snapshot)

The actual content/data stored in the database at a particular point in time.
