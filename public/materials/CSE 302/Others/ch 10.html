1. Introduction to Indexing, I/O Cost & Basic Concepts

সহজ বাংলায় ব্যাখ্যা (Slides 2–5)

১. Indexing কী? (Slide 2): ডাটাবেজ টেবিলের লক্ষ-কোটি রো (Row) প্রতিটি একে একে না খুঁজে খুব দ্রুত নির্দিষ্ট ডাটা খুঁজে বের করার পদ্ধতিকে Indexing বলে।
বাস্তব জীবনের উদাহরণ (Slide 5): একটি ৫০০ পৃষ্ঠার বইয়ের শুরুতে যেমন সূচিপত্র (Table of Contents / Index) থাকে—যেখান থেকে আমরা সরাসরি জানতে পারি কোন টপিক কত নম্বর পৃষ্ঠায় আছে—ঠিক তেমনি ডাটাবেজের সূচিপত্রই হলো Index File। লাইব্রেরিতে লেখকের নাম অনুযায়ী কার্ড ক্যাটালগ (Author catalog) খুঁজে বই বের করাও Indexing-এর উদাহরণ।

২. Why Indexing? এবং I/O Cost কী? (Slide 3):
• I/O Cost (Input/Output Cost): ডাটাবেজ থেকে কোনো রেকর্ড খোঁজা বা আপডেট করার সময় হার্ডডিস্ক থেকে কতবার ডাটা পড়তে (Disk Read) বা লিখতে (Disk Write) হয়, সেই সংখ্যাকে I/O Cost বলে। হার্ডডিস্ক থেকে ডাটা পড়া অনেক ধীরগতির কাজ। Indexing ব্যবহার করলে অল্প কয়েকটি ব্লক পড়েই কাঙ্ক্ষিত রেকর্ড পাওয়া যায়, ফলে I/O Cost অনেক কমে যায়।
• Primary Storage vs Secondary Storage (Slide 3):
— Primary Storage (যেমন: RAM / Main Memory): CPU সরাসরি এর ওপর কাজ করতে পারে। এটি খুব দ্রুতগতির, কিন্তু দামি এবং আকারে ছোট।
— Secondary Storage (যেমন: Hard Disk / SSD): এর ধারণক্ষমতা অনেক বড়, দাম কম, কিন্তু গতি ধীর। CPU সরাসরি হার্ডডিস্কের ডাটা প্রসেস করতে পারে না; আগে হার্ডডিস্ক থেকে ডাটা কপি করে Primary Storage (RAM)-এ আনতে হয়।

৩. সব ডাটা কেন Main Memory (RAM)-এ রাখা যায় না? (Slide 4):
১) Cost and Size: RAM-এর দাম হার্ডডিস্কের তুলনায় অনেক বেশি এবং এর জায়গা সীমিত (তাই টেরাবাইট বা পেটাবাইট ডাটা রাখা সম্ভব নয়)।
২) Volatile (অস্থায়ী মেমোরি): RAM হলো Volatile—অর্থাৎ কম্পিউটার বন্ধ হলে বা কারেন্ট চলে গেলে RAM-এর সব ডাটা চিরতরে মুছে যায়! তাই স্থায়ীভাবে ডাটা রাখতে Secondary Storage-ই ব্যবহার করতে হয়।

৪. Search Key এবং Index File-এর গঠন (Slide 5):
• Search Key: যে কলাম বা অ্যাট্রিবিউটের মান ব্যবহার করে আমরা ফাইলে রেকর্ড খুঁজি, তাকে Search Key বলে (যেমন: Student ID বা Instructor Name)।
• Index File & Index Entry: Index File মূল ডাটা ফাইলের চেয়ে আকারে অনেক ছোট হয়। এর প্রতিটি রেকর্ডের (Index Entry) দুটি অংশ থাকে:

search-key
pointer
← প্রতিটি Index Entry-তে একটি Search Key এবং মূল রেকর্ডের ঠিকানা (Pointer) থাকে।

Exam-Ready English Answer (5 Marks)

Definition of Indexing: Indexing is a data structure technique used in DBMS to quickly locate and access records in a database file without scanning every row sequentially.
Why Indexing is Needed (I/O Cost): Database files are stored on secondary storage (disk), which cannot be operated directly by the CPU and must be copied into primary storage (main memory). I/O cost refers to the number of disk read/write operations required to retrieve or update data. Indexing significantly reduces this I/O cost.
Why Not Store Everything in Main Memory? (1) Main memory is expensive and limited in size, and (2) Main memory is volatile, meaning all data is lost when power is turned off.
Search Key & Index File: A search key is an attribute or set of attributes used to look up records. An index file consists of compact records called index entries of the form <search-key, pointer>, making the index file much smaller than the original data file.

2. Indexing Methods: Ordered Index & Primary Index (Dense vs Sparse)

Classification of Indexing Methods (Slide 6)

সহজ বাংলায় ব্যাখ্যা (Slides 7–10)

১. Ordered Index (Slide 7): যে ইনডেক্সে Search Key-এর মানগুলো ছোট থেকে বড় (Sorted order) সাজানো থাকে, তাকে Ordered Index বলে।
২. Primary Index (Slide 8): যখন মূল ডাটা টেবিলটি তার Primary Key অনুযায়ী সাজানো (Sorted) থাকে এবং সেই Primary Key-এর ওপর ভিত্তি করে ইনডেক্স তৈরি করা হয়, তখন তাকে Primary Index বলে। যেহেতু Primary Key প্রতিটি রেকর্ডের জন্য অনন্য (Unique), তাই এখানে ১:১ (1:1) সম্পর্ক থাকে। এটি ২ প্রকার: Dense Index এবং Sparse Index।

Dense Index (Slide 9)

সংজ্ঞা: মূল টেবিলের প্রতিটি Search-key মানের জন্য ইনডেক্স ফাইলে একটি করে এন্ট্রি থাকলে তাকে Dense Index বলে। অর্থাৎ মূল টেবিলে ১২টি রেকর্ড থাকলে ইনডেক্স টেবিলেও ১২টি রেকর্ড থাকবে।
সুবিধা: খুব দ্রুত সরাসরি রেকর্ডে পৌঁছানো যায় (১ ধাপেই ঠিকানা পাওয়া যায়)।
অসুবিধা: ইনডেক্স ফাইলের আকার বড় হয় এবং নতুন রেকর্ড যোগ/মুছলে সব এন্ট্রি আপডেট করতে হয়।

Slide 9 Example (Every ID in Index):
Index [10101] ──▶ [10101 | Srinivasan | Comp. Sci. | 65000]
Index [12121] ──▶ [12121 | Wu | Finance | 90000]
Index [15151] ──▶ [15151 | Mozart | Music | 40000]
... (All 12 instructor IDs have index entries)

Sparse Index (Slide 10)

সংজ্ঞা: মূল টেবিলের সব রেকর্ডের জন্য নয়, বরং কিছু নির্দিষ্ট (যেমন প্রতিটি ব্লকের প্রথম) Search-key মানের জন্য ইনডেক্স এন্ট্রি থাকলে তাকে Sparse Index বলে। শর্ত হলো: মূল ফাইলটি অবশ্যই Search Key অনুযায়ী সাজানো থাকতে হবে।
কীভাবে কাজ করে (Slide 10)? ধরো আমরা K = 22222 (Einstein) খুঁজছি, কিন্তু ইনডেক্সে শুধু 10101, 32343, 76766 আছে। সিস্টেম প্রথমে 22222-এর চেয়ে ছোট বা সমান সবচেয়ে বড় মান 10101 খুঁজে তার পয়েন্টার ধরে মূল টেবিলে যাবে, এবং সেখান থেকে নিচে স্ক্যান (Sequential search) করে 22222 বের করবে!
সুবিধা: ইনডেক্স ফাইল খুব ছোট হয় এবং মেমোরি কম লাগে।

Slide 10 Example (Only 3 entries for 12 rows):
Index [10101] ──▶ [10101 | Srinivasan] → (scan down to 22222)
Index [32343] ──▶ [32343 | El Said]
Index [76766] ──▶ [76766 | Crick]
Feature Dense Index Sparse Index
Index Entries Contains an index entry for every search-key value in the file. Contains index entries for only some search-key values (e.g., one per block).
Size & Space Requires more storage space (larger index file). Requires much less space and maintenance overhead.
Search Speed Faster lookup (direct pointer to exact record). Slightly slower (requires sequential scan inside the target block).
File Ordering Requirement Can work even if data records are not sequentially ordered (in secondary dense index). Strictly requires the data file to be physically sorted on the search key.

3. Clustering Index & Secondary Index (Slides 11–15)

সহজ বাংলায় ব্যাখ্যা: Clustering Index ও Secondary Index

১. Clustering Index কী? (Slides 11, 12 & 13):
ধরো আমাদের টেবিলটি Primary Key (ID) অনুযায়ী সাজানো নয়, বরং একটি Non-key attribute (যেমন: dept_name বা Dept_ID) অনুযায়ী শারীরিকভাবে সাজানো (Physically Sorted) আছে! অর্থাৎ Biology ডিপার্টমেন্টের সব শিক্ষক একসাথে, তারপর Comp. Sci.-এর সব শিক্ষক একসাথে, তারপর Elec. Eng.-এর সব শিক্ষক একসাথে।
• এখানে dept_name কোনো Primary Key নয় (কারণ একাধিক শিক্ষকের ডিপার্টমেন্ট একই হতে পারে — Non-unique key)।
• প্রতিটি ইউনিক ডিপার্টমেন্টের নামের জন্য ইনডেক্স টেবিলে মাত্র একটি করে এন্ট্রি থাকে যা ওই ডিপার্টমেন্টের প্রথম রেকর্ডটিকে নির্দেশ করে। যদি একটি ব্লকে সব রেকর্ড না ধরে, তবে Block-level pointer দিয়ে পরের ব্লকগুলো যুক্ত থাকে (Slide 11 & 13)।

২. Secondary Index কী? (Slides 14 & 15):
মূল ডাটা টেবিলটি সাধারণত Primary Key (যেমন ID: 10101, 12121, 15151...) অনুযায়ী সাজানো থাকে। এখন তুমি যদি এমন একটি কলামের ওপর সার্চ করতে চাও যা দিয়ে টেবিলটি সাজানো নয় (যেমন: salary — 40000, 60000, 62000...), তবে মূল টেবিলের সাজানো ক্রম নষ্ট না করে আলাদা একটি সাজানো ইনডেক্স তৈরি করা হয়—একেই Secondary Index বলে।
• কীভাবে কাজ করে (Slide 15)? যেহেতু একই বেতন (যেমন 80000) একাধিক শিক্ষকের (Singh, Kim) থাকতে পারে এবং মূল টেবিলে তারা ছড়িয়ে-ছিটিয়ে আছে, তাই Secondary Index-এর এন্ট্রিটি সরাসরি রেকর্ডে না গিয়ে মাঝখানের একটি Intermediate Layer (Bucket of record pointers)-এ পয়েন্ট করে। সেই বাকেটে 80000 বেতন পাওয়া সব শিক্ষকের ঠিকানা (Pointers) জমা থাকে!
• মনে রাখার কৌশল: Secondary Index সবসময় Dense হতে হয় (কারণ মূল টেবিলটি ওই কলাম অনুযায়ী সাজানো নেই)।

Criteria Primary Index Clustering Index Secondary Index
Attribute Type Built on Primary Key (Unique values). Built on Non-key attribute (Duplicate values allowed). Built on Non-ordering attribute (Candidate key or non-key).
Physical Ordering of Data File Data file is physically sorted on this Primary Key. Data file is physically sorted on this Non-key field. Data file is NOT sorted on this field (sorted by another key).
Dense or Sparse? Can be either Dense or Sparse. Usually Sparse (one entry per distinct key value). Must be Dense (uses pointer buckets for duplicates).
Number per Table At most 1 per table. At most 1 per table (mutually exclusive with Primary). Can have many secondary indexes per table.

4. B+ Tree Index Files: Structure, Nodes & Mathematical Properties

একদম শূন্য থেকে B+ Tree কী এবং কেন? (Slides 16–22)

সাধারণ Sequential Index ফাইল বড় হতে থাকলে তাতে নতুন রেকর্ড ইনসার্ট বা ডিলিট করা খুব ধীরগতির হয়ে যায়। এই সমস্যা সমাধানে B+ Tree ব্যবহৃত হয়, যা একটি স্বয়ংক্রিয়ভাবে ব্যালেন্সড (Self-balancing) Multi-level Tree Index।

  • Root Node (মূল নোড): গাছের একদম উপরের নোড, যেখান থেকে যেকোনো সার্চ শুরু হয়।
  • Internal / Non-leaf Node (অভ্যন্তরীণ নোড — Slide 20): Root এবং Leaf-এর মাঝখানের নোডগুলো। এরা শুধু পথনির্দেশক (Routing/Guide) হিসেবে কাজ করে—অর্থাৎ কোন দিকে গেলে কাঙ্ক্ষিত ডাটা পাওয়া যাবে তা বলে দেয়। এদের কোনো ডাটা রেকর্ডের সাথে সরাসরি পয়েন্টার থাকে না।
  • Leaf Node (পাতা নোড — Slide 21): গাছের একদম নিচের স্তরের নোডগুলো। সব আসল Search Key এবং ডাটা রেকর্ডের পয়েন্টার শুধু Leaf Node-এ থাকে! এছাড়া প্রতিটি Leaf Node-এর ডানপাশে একটি পয়েন্টার থাকে যা পাশের (পরবর্তী) Leaf Node-কে যুক্ত করে (Linked List-এর মতো), যাতে রেঞ্জ কুয়েরি (যেমন: ১০ থেকে ৫০ পর্যন্ত সব ডাটা দেখাও) খুব দ্রুত করা যায়।
  • কেন সব Leaf Node একই লেভেলে (Same Level) থাকে? (Slide 18): কারণ B+ Tree একটি Balanced Tree। Root থেকে যেকোনো Leaf Node-এ যেতে সমান সংখ্যক ধাপ (Disk I/O) লাগে, ফলে প্রতিটি সার্চের সময় সমান ও অত্যন্ত দ্রুত হয়।

B+ Tree Rules for Order = n (Slide 18 & 22)

Node Type Minimum Maximum
Non-leaf (Internal) Children ⌈n / 2⌉ n
Non-leaf (Internal) Keys ⌈n / 2⌉ - 1 n - 1
Leaf Node Keys (Values) ⌈(n - 1) / 2⌉ n - 1
Root Node (when not leaf) 2 children (1 key) n children (n-1 keys)

Slide 22 Check (n = 6): Leaf keys = ⌈5/2⌉ = 3 to 5. Non-leaf children = ⌈6/2⌉ = 3 to 6.

Slide 23 & 24 Setup & Golden Rules (খুব মনোযোগ দিয়ে পড়ো!)

Order, n = 4
• Non-leaf Max children = 4 (Max keys = 3)
• Non-leaf Min children = ⌈4/2⌉ = 2 (Min keys = 1)
• Leaf node Max keys = (4 - 1) = 3
• Leaf node Min keys = ⌈(4 - 1)/2⌉ = ⌈1.5⌉ = 2

B. 5-Second Final B+ Tree Validation Checklist

  1. Count All Input Keys: সব ইনপুট ডাটা নিচের Leaf Node গুলোতে ছোট থেকে বড় সাজানো অবস্থায় আছে কি না গুনে দেখো।
  2. Check Leaf Node Limits: প্রতিটি Leaf-এ ⌈(n-1)/2⌉ থেকে n-1 সংখ্যক কী আছে কি না দেখো।
  3. Check Internal Node Limits: প্রতিটি Internal Node-এ ⌈n/2⌉ থেকে n সংখ্যক Child এবং (Children - 1) সংখ্যক কী আছে কি না দেখো।
  4. No Duplicate Internal Keys: কোনো একটি কী একই সাথে দুটি Internal/Root নোডে আছে কি না দেখো (থাকলে ভুল হয়েছে)।
  5. Same Depth + Leaf Links: সব Leaf Node একদম একই সারিতে আছে কি না এবং বাম থেকে ডানে তীর দিয়ে যুক্ত কি না চেক করো।

C. Common Exam Mistakes & How to Avoid Them

  • ভুল ১ (Leaf Split-এ কী মুছে ফেলা): Leaf Node ভাগ করার সময় প্রোমোট করা কী-টি (যেমন 7 বা 17) ডান পাশের Leaf থেকে মুছে ফেলবে না—এটি ডান Leaf-এ কপি হয়ে থাকবে।
  • ভুল ২ (Internal Split-এ কী রিপিট করা): Slide 36 অনুযায়ী Internal বা Root নোড ভাগ করার সময় মাঝের কী-টি (যেমন 20) উপরে উঠে যাবে, নিচের Internal নোডে রিপিট হবে না।
  • ভুল ৩ (Splitting Bias পরিবর্তন করা): শুরুতে যদি Right-biased (4 ও 7-এর মধ্যে 7) ধরো, তবে পুরো অংকে সব সময় Right-biased নিয়মই অনুসরণ করতে হবে।
  • ভুল ৪ (Leaf Pointer না আঁকা): পরীক্ষার খাতায় অবশ্যই নিচের Leaf Node গুলোর মাঝে বাম থেকে ডানে সংযোগকারী তীর চিহ্ন (Next leaf pointer) আঁকবে।

5-Mark Exam Answer: What is a B+ Tree & Its Properties?

A B+ Tree is a balanced multi-level tree index structure that automatically reorganizes itself with small, local changes upon insertions and deletions. For a B+ tree of order n:
1. All search-key values in a node are kept in sorted order.
2. All paths from the root to every leaf node are of the exact same length.
3. Each internal (non-leaf, non-root) node has between ⌈n/2⌉ and n children.
4. Each leaf node holds between ⌈(n-1)/2⌉ and n-1 key values, and all leaf nodes are linked sequentially to support fast range queries.

5-Mark Exam Answer: Dense Index vs Sparse Index

Dense Index: An index record appears for every search-key value in the data file. It enables direct, fast access to any record, but requires more storage space and higher maintenance cost during insertions/deletions.
Sparse Index: Index records are created for only some of the search-key values (typically one entry per disk block). It requires significantly less space, though it strictly requires the data file to be physically sorted on the search key and needs a short sequential scan within the block.
