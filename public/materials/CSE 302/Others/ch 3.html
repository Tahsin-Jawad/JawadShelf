এখানে আমরা Relational Model এর বেসিক কনসেপ্ট, টেবিল, রো, কলাম, এবং ডাটাবেজ সুরক্ষার জন্য অত্যন্ত গুরুত্বপূর্ণ বিভিন্ন ধরনের Keys এবং Integrity Constraints সহজ বাংলায় শিখব।

1. Relational Model Concepts & Terminology

Lecture 3.1 • Slides 2–4

Relational Model এ পুরো ডাটাবেজকে কতগুলো টেবিলের (Tables) কালেকশন হিসেবে স্টোর করা হয়। প্রতিটি টেবিলকে বলা হয় একটি Relation।

Relation

একটি পুরো টেবিলকে (যেমন: Student) relation বলা হয়।

Tuple

টেবিলের প্রতিটি row বা রেকর্ডকে tuple বলে। এটি একটি রিয়েল-ওয়ার্ল্ড অবজেক্ট নির্দেশ করে।

Attribute

টেবিলের প্রতিটি column header হলো attribute (যেমন: ID, Name)।

উদাহরণস্বরূপ Student Table:

Student_ID Name Department
101 Rahim CSE
102 Karim EEE
Senior's Note (সোজা বাংলায়):

"এখানে মূল ব্যাপারটা হচ্ছে—আমরা নরমাল লাইফে যেগুলোকে টেবিল, রো আর কলাম বলি, ডাটাবেজ থিওরিতে স্যার ঠিক সেগুলোকে যথাক্রমে Relation, Tuple এবং Attribute বলে ডাকেন!"

Domains & Atomicity

  • Domain: প্রতিটি attribute এর জন্য ভ্যালুর একটি নির্দিষ্ট এলাউড সেট থাকে (যেমন: BD Phone numbers = 11 digits, Age = 15 to 80 integers)।
  • Atomicity: এটমিক মানে হলো ভ্যালু অবশ্যই single এবং indivisible (অবিভাজ্য) হতে হবে। যেমন: ফুল নেমকে First Name ও Last Name এ ভাগ করা যায় যাতে ভ্যালুগুলো এটমিক থাকে।
  • NULL Value: যেকোনো ডোমেইনের সদস্য হলো বিশেষ ভ্যালু NULL, যার অর্থ হলো মানটি "unknown" বা অজানা।

2. Relations are Unordered

Lecture 3.1 • Slide 5

ডাটাবেজ টেবিলের ক্ষেত্রে tuples (rows) এর অর্ডার সম্পূর্ণ irrelevant বা গুরুত্বহীন। টাপলগুলো যেকোনো অর্ডারে স্টোর হতে পারে। আপনি প্রথমে কাকে ইনসার্ট করলেন বা পরে কাকে করলেন তাতে টেবিলের লজিক্যাল মিনিং বদলায় না।

যেমন: instructor টেবিলে রেকর্ডগুলো র‍্যান্ডম অর্ডারে থাকতে পারে, সার্চ করার সময় কোয়েরি অনুযায়ী সাজিয়ে নেওয়া হয়।

3. Relation Schema & Relation Instance

Lecture 3.1 • Slide 6

Relation Schema

এটি হলো টেবিলের লজিক্যাল স্ট্রাকচার বা ব্লুপ্রিন্ট। যেমন:
instructor = (ID, name, dept_name, salary)

Relation Instance

এটি হলো নির্দিষ্ট কোনো মুহূর্তে টেবিলে থাকা আসল ডাটা বা রেকর্ডসমূহ। একে r(R) দ্বারা প্রকাশ করা হয়।

4. Database & Why We Split Information into Multiple Relations

Lecture 3.1 • Slide 7

একটি ডাটাবেজে একাধিক relation থাকে। পুরো ব্যাংকের ইনফরমেশন একটিমাত্র বিশাল টেবিলে (যেমন: bank(account_number, balance, customer_name, ...)) না রেখে আলাদা আলাদা টেবিলে ভাগ করা হয় (account, depositor, customer)।

একবিশাল টেবিলে রাখলে কি সমস্যা হতো?

1. Repetition of Information

একই কাস্টমারের একাধিক অ্যাকাউন্ট থাকলে তার নাম ও ঠিকানা বারবার রিপিট হতো (Redundancy)।

2. Need for NULL Values

অ্যাকাউন্ট নেই এমন কাস্টমার যুক্ত করতে গেলে অ্যাকাউন্ট ফিল্ডে জোর করে NULL বসাতে হতো।

💡 Normalization Theory: এই সমস্যাগুলো দূর করে কিভাবে প্রপারলি টেবিল ডিজাইন করতে হয় তা Normalization থিওরি শেখায়।

6. Super Key

Lecture 3.1 Slides 9–10 • Ref Slides 10–15

একটি টেবিলের এমন যেকোনো কম্বিনেশন বা অ্যাট্রিবিউট সেট যার ভ্যালু দিয়ে টেবিলের প্রতিটি রো কে ইউনিকলি চেনা যায়, তাকে Super Key বলে। সহজ কথায়, Super Key হলো Candidate Key এর একটি superset (Candidate key + 1 or more attributes)।

উদাহরণ টেবিল:

Student_ID Student_Enroll Student_Name Student_Email
S024545Daveddd@gmail.com
S344541Jackjjj@gmail.com
S224555Markmmm@gmail.com
Possible Super Keys here:
• {Student_ID}
• {Student_Enroll}
• {Student_Email}
• {Student_ID, Student_Enroll}
• {Student_ID, Student_Name}
• {Student_ID, Student_Enroll, Student_Name, Student_Email}

7. Candidate Key

Lecture 3.1 Slide 11 • Ref Slide 6

Super Key এর মধ্যে যেগুলোর কোনো অপ্রয়োজনীয় বা অতিরিক্ত অ্যাট্রিবিউট নেই—অর্থাৎ একদম minimal (minimal super key)—সেগুলোকে বলা হয় Candidate Key।

উপরে উল্লেখিত টেবিলের Candidate Key গুলো হলো:

👉 {Student_ID}, {Student_Enroll}, {Student_Email}

8. Primary Key & SQL Implementation

Lecture 3.1 Slide 12 • Ref Slide 7

একাধিক Candidate Key থেকে সবচেয়ে উপযুক্ত একটি key কে টেবিলে প্রধান শনাক্তকারী হিসেবে সিলেক্ট করা হয়, যাকে বলে Primary Key।

Primary Key Rules

  • Must be UNIQUE (কোনো ডুপ্লিকেট থাকতে পারবে না).
  • Must NOT contain NULL values.
  • যেকোনো এমন অ্যাট্রিবিউট সিলেক্ট করা উচিত যার মান সচরাচর বদলায় না (যেমন email unique হলেও পরে বদলাতে পারে)।

Candidate vs Primary

Candidate key তে null থাকতে পারলেও Primary key তে কোনো অবস্থাতেই null থাকতে পারবে না।

SQL CREATE TABLE (Primary Key) 
CREATE TABLE Persons (
    ID int NOT NULL,
    LastName varchar(255) NOT NULL,
    FirstName varchar(255),
    Age int,
    PRIMARY KEY (ID)
);

9. Foreign Key & Table Relations

Lecture 3.1 Slides 13, 19–20 • Ref Slides 18–20

একটি টেবিলের যে অ্যাট্রিবিউট অন্য টেবিলের Primary Key কে রেফার করে বা নির্দেশ করে, তাকে Foreign Key বলে। এর মাধ্যমে দুটি টেবিলের মধ্যে সম্পর্ক তৈরি হয় (Parent Table & Child Table)।

SQL Syntax:

FOREIGN KEY (columnName) REFERENCES tablename(columnName)

10. Secondary Key / Alternate Key

Lecture 3.1 Slide 14

একটি টেবিলে একাধিক candidate key থাকতে পারে। তার মধ্য থেকে একটিকে প্রাইমারি কি হিসেবে সিলেক্ট করার পর বাকি যে candidate key গুলো থেকে যায়, সেগুলোকে Secondary Key বা Alternate Key বলে।

⚠️ Note: Secondary Key কখনোই Foreign Key নয়! এটি মূলত unused candidate key যা দিয়েও স্পেসিফিক রেকর্ড লোকেট করা যায়।

11. Unique Key

Lecture 3.1 Slide 15 • Ref Slides 8–9

কোনো কলামে ডুপ্লিকেট ভ্যালু রোধ করার জন্য Unique Key ব্যবহার করা হয়। প্রাইমারি কি এবং ইউনিক কি এর মধ্যে মূল পার্থক্য হলো—প্রাইমারি কি তে কোনো NULL থাকতে পারে না, কিন্তু Unique Key টেবিলে মাত্র একটি NULL ভ্যালু এলাউ করে। এছাড়া একটি টেবিলে একাধিক Unique Key থাকতে পারে।

SQL CREATE TABLE (Unique Key) 
CREATE TABLE Persons (
    ID int NOT NULL UNIQUE,
    LastName varchar(255) NOT NULL,
    FirstName varchar(255),
    Age int
);

12. Composite Key

Lecture 3.1 Slide 16

যখন একটিমাত্র কলাম দিয়ে ইউনিকলি রো শনাক্ত করা যায় না, তখন দুই বা ততোধিক কলামের কম্বিনেশনকে প্রাইমারি কি হিসেবে ব্যবহার করা হয়। একে Composite Key বলে।

13. Integrity Constraints

Lecture 3.1 Slides 17–20

ডাটাবেজে সংরক্ষিত ডাটার সঠিকতা এবং নির্ভুলতা নিশ্চিত করতে Integrity Constraints ব্যবহার করা হয়। এগুলো ৪ প্রকার:

1. Domain Constraint

অ্যাট্রিবিউটের ভ্যালু নির্দিষ্ট ডোমেইন বা ডাটা টাইপের (যেমন integer, string, date) মধ্যে থাকতেই হবে। (যেমন: Age কলামে 문자 'A' দেওয়া যাবে না)।

2. Entity Integrity Constraint

প্রাইমারি কি এর মান কখনোই NULL হতে পারবে না। কারণ null হলে রো চেনা সম্ভব নয়।

3. Referential Integrity Constraint

ফরেইন কি এর ভ্যালু অবশ্যই প্যারেন্ট টেবিলের প্রাইমারি কি তে উপস্থিত থাকতে হবে অথবা NULL হতে হবে।

4. Key Constraint

প্রতিটি টেবিলে ইউনিক রেকর্ড আইডেন্টিফিকেশনের জন্য কি রুলস বজায় রাখা।

Quick Revision (Exam Cheat Sheet)

পরীক্ষার আগে একনজরে সবচেয়ে গুরুত্বপূর্ণ কনসেপ্টগুলো দেখে নিন

1. Relation & Terminology

Table = Relation, Row = Tuple, Column = Attribute. Order of tuples is irrelevant.

2. Super Key vs Candidate Key

Super key হলো যেকোনো ইউনিক কম্বিনেশন (Superset)। আর minimal super key হলো Candidate Key।

3. Primary Key Rules

Unique + NOT NULL. টেবিলে মাত্র একটিই প্রাইমারি কি থাকতে পারে।

4. Foreign Key

রেফারেন্স কি যা অন্য টেবিলের Primary Key কে পয়েন্ট করে টেবিলের মধ্যে সম্পর্ক তৈরি করে।
